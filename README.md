# Лабораторная работа 3, вариант 11

Программа применяет медианный фильтр к целочисленной матрице несколько раз.
Граничные элементы повторяются. Каждый проход читает предыдущую матрицу
и записывает результат в другой буфер.

## Сборка и запуск

Из папки `lab_03`:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
cd build
```

Весь ввод читается из stdin в таком порядке:

```text
iterations radius max_threads
rows cols
элементы матрицы построчно
```

Например:

```text
1 1 4
2 3
10 20 30
40 50 60
```

Это один проход, радиус 1 (окно 3×3), четыре рабочих потока.
Главный поток занимается управлением и не входит в указанное число рабочих.

Результат выводится в stdout: сначала `rows cols`, затем матрица.
Приглашения ко вводу, PID/TID и сообщения об ошибках выводятся в stderr,
поэтому они не попадают в файл при обычном перенаправлении stdout.

Интерактивный запуск:

```bash
./median_filter
```

Запуск с перенаправлением из `build`:

```bash
./median_filter < ../data/input_100x100.txt > ../data/out.txt
```

Диагностика при этом остаётся в терминале. Её можно сохранить отдельно:

```bash
./median_filter < ../data/input_100x100.txt > ../data/out.txt 2> ../threads.log
```

Программа не открывает входной и выходной файлы самостоятельно.
`>` перезаписывает файл результата; `>>` дописывает в конец.

## Тестовые входные файлы

В каждом файле первая строка — `1 1 4`, вторая — размеры, далее матрица.
Все значения находятся в диапазоне 0..255 и сгенерированы воспроизводимо.

| Файл | Строки × столбцы | Элементов |
|---|---|---|
| `data/input_10x10.txt` | 10×10 | 100 |
| `data/input_20x50.txt` | 20×50 | 1 000 |
| `data/input_100x100.txt` | 100×100 | 10 000 |
| `data/input_200x500.txt` | 200×500 | 100 000 |
| `data/input_1000x1000.txt` | 1000×1000 | 1 000 000 |

## Фотография → матрица → фотография

Для Python нужна Pillow. Подготовка из папки `lab_03`:

```bash
python3 -m venv --without-pip .venv
python3 -m pip --python .venv/bin/python install -r utils/requirements.txt
```

Из папки `build`:

```bash
../.venv/bin/python ../utils/image_to_matrix.py
{ printf '1 1 4\n'; cat ../data/in.txt; } | ./median_filter > ../data/out.txt
../.venv/bin/python ../utils/matrix_to_image.py
```

Первая утилита читает `data/image.png`, в памяти переводит изображение
в оттенки серого и перезаписывает `data/in.txt`.
Она сохраняет только размеры и матрицу яркости, без параметров фильтра.
Поэтому команда выше сначала подаёт программе `1 1 4`,
а затем содержимое матрицы. Исходное изображение остаётся без изменений.

Вторая утилита читает размеры и значения из `data/out.txt` и сохраняет
изображение в оттенках серого в `data/image_out.png`.

Пути в утилитах фиксированы и вычисляются относительно расположения скриптов.
Аргументы командной строки не требуются.

В VS Code открой нужный Python-файл и нажми «Запуск файла Python».
Для проекта настроен интерпретатор `lab_03/.venv/bin/python`, в котором
установлена Pillow. При первом применении этих настроек выполни
`Developer: Reload Window`.
Запуск через абсолютный путь `/bin/python3` использует системный Python
даже при активированном окружении `.venv`.

## Что показывает фильтр

Медиана заменяет выбивающиеся значения типичными значениями соседей:
например, окно `10 10 10 / 10 255 10 / 10 10 10` заменит центральное 255 на 10.
Повторные проходы дополнительно сглаживают матрицу, но могут удалять мелкие
детали. Несколько проходов маленьким окном не равны одному проходу большим.

Изображение представлено одной матрицей яркости: ширина и высота матрицы
совпадают с шириной и высотой изображения.
